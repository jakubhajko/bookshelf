# Dataset layout

This directory is **not version-controlled** (see repo `.gitignore`) except for this
file, `sample/`, and `.gitkeep` placeholders. Everything else is either a large raw
source dump or a derived artifact that can be rebuilt from those sources.

## `raw/`

Original, unmodified third-party sources. Nothing here is read directly by the
application; `data/notebooks/build_dataset.ipynb` consumes it to produce `processed/`.

- `raw/goodreads/` — the UCSD Goodreads dump (`goodreads_books.json` ~8.6 GB,
  `goodreads_book_authors.json`, `goodreads_book_genres_initial.json`). Books are
  streamed and filtered while building the dataset; the full file is never loaded
  into memory at once and is never read by the API.
- `raw/book-crossing/` — the Book-Crossing dataset (`Books.csv`, `Ratings.csv`,
  `Users.csv`) plus a few reference diagrams bundled with the original download
  (`DeepRec.png`, `classicRec.png`, `recsys_taxonomy2.png`). Book-Crossing ratings
  are the source of the `bx_ratings` / `bx_explicit` rollup columns on `books.parquet`
  (see spec §7.1) and are joined in by normalized ISBN.

## `processed/`

The canonical, work-deduplicated dataset described in `APP_SPECIFICATION.md` §7
(now at `archive_of_structural_prompts/app_building_prompts/`).
This is what the Phase 2 import adapter reads — never the contents of `raw/`.

- `books.parquet` — 92,526 rows, one per canonical work, 39 columns, unique
  `work_id`. **Known data-quality issues, both handled by the import adapter's
  per-row validation (reported, not silently dropped — see plan.md §6):**
  one row has `work_id == ""` (empty string, not null); one row
  (`work_id='2440582'`, row 41150) has a title that is empty/whitespace
  after stripping. 92,524 of 92,526 rows import cleanly.
- `interactions.parquet` — 775,090 rows, 83,200 historical users × 92,526 works,
  no duplicate `(user_id, work_id)` pairs, no timestamps. `rating == 0` means an
  implicit interaction (shelved but never scored), not a negative signal — 474,910
  rows (61.3%). Ratings 1–10 are explicit (300,180 rows). These historical
  `user_id`s are training identities only and must never become application users
  (spec §6.7).
- `covers/` — 102,435 local cover images named `<isbn>.jpg`, referenced by
  `books.parquet.cover_file`. The Phase 2 local storage backend serves these; the
  API must resolve paths safely (no traversal) and must not construct cover paths
  in the frontend.
- `covers_manifest.parquet`, `books_editions.parquet`, `interactions_editions.parquet`
  — intermediate, edition/ISBN-level build artifacts already rolled up into the
  work-level tables above (`n_editions`, `edition_isbns`, `bx_ratings`,
  `bx_explicit`, `cover_file`, `cover_source`). Per spec §2/§5.1 the app does not
  model a separate edition entity, so these three files are kept only for dataset
  provenance/rebuilding and are **not** import inputs.

## `notebooks/`

`build_dataset.ipynb` — turns `raw/` into `processed/` (streaming JSON pass,
ISBN normalization, edition→work merge, cover backfill, sanity checks).
`inspect_goodreads.ipynb` — exploratory analysis of the raw dump.
`.feature_cache.pkl` — an intermediate execution cache for the build notebook
(safe to delete and regenerate by re-running the notebook).

## `sample/`

The small, checked-in Parquet fixture used by integration tests (spec
§13.3): `books.parquet` (301 rows, real metadata) + `covers/` (151 files),
generated by `scripts/data_import/build_sample_fixture.py` (deterministic
seed, not hand-authored) rather than committed by hand. Deliberately keeps
the `work_id == ""` row from the full dataset so the importer's rejection
path is tested against real data. Regenerate after
`data/processed/books.parquet` changes:

**`covers/` contains placeholder files, not real cover art.** The real
files in `data/processed/covers/` are copyrighted book covers scraped from
Goodreads/Open Library (see `processed/` above) — fine to keep locally
(gitignored), but not fine to redistribute by committing them to a git
repo. `tests/integration/test_local_covers.py` only asserts that
`LocalFileStorage` resolves the right filename to an existing, safely-scoped
path; it never reads image bytes, so a placeholder is exactly as good a
fixture as the real file and carries no copyright risk.

```bash
uv run --project apps/api python scripts/data_import/build_sample_fixture.py
```

## `artifacts/`

Empty placeholder for generated model artifacts (spec §10.13 — popularity
provider output starting Phase 5, later the future pipeline). Gitignored
except for `.gitkeep`: everything here is regeneratable via CLI (eventually
`make build-popularity`), never hand-edited or committed. This is the default
`artifact_storage_local_path` in `Settings` (`core/config.py`) and the
read-only mount target for the `api` service in `docker-compose.yml`.
